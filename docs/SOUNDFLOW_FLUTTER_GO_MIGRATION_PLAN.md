## 0. TL;DR

- **Что переносим — «мозг»:** продуктовые потоки экранов, стейт-машины плеера/Потока,
  алгоритм офлайн-радио (`offlineVibe.ts`), скоринг вайба (`vibe/scoring.ts`, λ=0.6),
  вся SQL-бизнес-логика (чарты, качество/версии, лайки/корзина, офлайн-манифест), схема БД.
- **Что переписываем — «тело»:** весь UI, аудио-слой, работа с файлами/сетью/загрузчиком
  (Web Audio + Capacitor-плагины → `just_audio`/`audio_service` + нативные Flutter-пакеты).
- **Что выбрасываем:** пласт веб-костылей (mixed-content прокси, двойное хранилище
  IndexedDB+SQLite со сверкой, лечение битого кэша по code 4, tRPC), зоопарк источников
  (SoundCloud/Soulseek), мультиюзерность, temporary-quick-skip-blacklist.
- **Ключевая развилка (рекомендация):** Go переписывает `apps/api` целиком; **тонкий
  Python-сайдкар оставляем** — yt-dlp, PANNs-эмбеддинги, librosa, curl_cffi (обход Cloudflare)
  на Go не переносятся дёшево. Контракт API↔сайдкар уже HTTP-JSON — Go дергает те же ручки.
- **Первый этап:** скелет Flutter (5 вкладок-заглушек) + Go (health, логин Alex, токен),
  Postgres/SQLite поднимаются, тестовая папка музыки, офлайн-вход после первого логина.

- **Вайб** (`apps/api/src/vibe/`): PANNs-эмбеддинги 2048-D (pgvector `<=>`), центроид вкуса

- **Лайки/корзина**: `user_liked_tracks`, `user_track_blacklist` (permanent/temporary), корзина.

## 2. Что переносим (концептуально — «мозг»)

Не зависит от Svelte/Bun, переносится идеями/алгоритмами/SQL:
- **Информационная архитектура и потоки экранов** — почти 1:1 (5 вкладок, онбординг, Корзина, альбом).
- **Алгоритм офлайн-радио `offlineVibe.ts`** — чистые функции (скоринг, explore/exploit, пороги
  настроения, веса событий play+1/like+4/skip−1/dislike−6). **Портируется в Dart почти дословно —
  самый ценный переиспользуемый кусок.**
- **Скоринг вайба сервера** (`vibe/scoring.ts`, `config.ts`, λ=0.6, diversity, explore-лестница) —
  чистая математика, переносится в Go 1:1.
- **Подбор в Postgres** (центроид `AVG(feature_vector)`, cosine `<=>`, pgvector) — Go шлёт тот же SQL.
- **SQL-бизнес-логика**: чарт-витрины (`chart-jobs.ts`), качество/версии (`audio-quality.ts`,
  `best-version.ts`, `track-quality.ts` — пороги/сравнение/дедуп), retry-policy, prefetch-budget,
  reject, normalize-key, лайки/blacklist/корзина, офлайн-манифест, статистика — в Go идеально.
- **Схема SQLite телефона** (`db.ts`) и репозитории → на `sqflite` почти без изменений (идея
  `track_key` по контенту сохраняется).
- **Семантика офлайн-очереди** (`offlineQueue.ts`): виды действий, drain по online, 4xx-дроп/5xx-повтор.
- **Оркестрация докачки** (`offlineDownload.svelte.ts`): манифест, scope, зеркалирование с PRUNE_FLOOR,
  LRU-бюджет, чёрный список негодных, wifi-only, resume — стейт-машина переносится.
- **Настройки** (`waveSettings/soundSettings/downloadSettings`) → `shared_preferences`.
- **Продуктовые требования звука**: −14 LUFS, мягкий переход, лимитер (реализация другая).

## 3. Что выбрасываем / упрощаем

Существенный бонус: в нативном Flutter исчезает целый пласт веб-костылей.
- **Mixed-content обход** (прокси-стрим, токен-в-URL, `cacheCoverFile`, материализация Content-Length)
  — существует ТОЛЬКО потому, что Android WebView не играет http-поток с https-страницы. В нативе
  не нужно: обычный HTTP-клиент с auth-заголовками. Большое упрощение медиа-раздачи и `TrackCover`.
- **Двойное хранилище IndexedDB + SQLite и вся сверка/reconcile/prune/mirror** — артефакт
  ненадёжного IndexedDB в WebView. В Flutter схлопывается в **один SQLite** (единственный источник
  правды); фантомы/орфаны/анти-wipe/«правда диска vs реестр» выбрасываются.
- **Web Audio граф** (AudioContext/Gain/Compressor/MediaElementSource, fade-узлы, HTMLAudioElement,
  события stalled/waiting/error-code-4, лечение битого кэша) → `just_audio` их не имеет.
- **tRPC** — TS-only, в Dart нет. Контракт → REST/OpenAPI (или Connect-RPC).
- **Зоопарк источников**: по новому плану — только Яндекс + официальные торренты. SoundCloud/Soulseek
  выбрасываем; ленивый resolve temp-стримов и часть провайдер-плоскости сильно упрощается.
- **Мультиюзерность** (`user_id` везде, роли, инвайты, web-создание юзеров) → single-user Alex
  (связку `user_id` оставить на будущее для реестра устройств/админки).
- **Temporary/quick-skip blacklist** (14 дней) → сводится к дизлайку + Корзине 7 дней.
- **Pixi.js/GSAP/Aurora, view-transitions, build-id-инвалидация, single-user авто-логин-костыль** —
  переписываются нативно (`palette_generator`, обычная анимация Flutter, нативная сессия).

## 4. Новая архитектура

Граница-инвариант: **телефон главный, играет офлайн; сервер — помощник дома.**
- **Телефон (Flutter, Android сначала).** Скачанная музыка + SQLite. Играет полностью офлайн из
  локального кэша. Копит события в локальную очередь. Синк — только дома по Wi-Fi.
- **Сервер (Go на fg + тонкий Python-сайдкар).** Postgres — полный каталог, эмбеддинги, статистика,
  чарты. Ищет/качает музыку (через сайдкар), проверяет качество, готовит пакет Потока на 24ч,
  обновляет чарты 1×/день, принимает события (дедуп по uuid), считает подбор. До 500ГБ.
- Каждая фича проверяется на офлайн-инвариант: работает ли без сети из SQLite.

```
    repo/                  — репозитории (library/stream/charts/events/storage)
    sync/                  — синхронизатор (connectivity_plus, батч событий, дедуп)
  features/
    stream/                — Поток: только скачанное, статус запаса, реакции

    library/               — Скачано/Любимое/Альбомы/История/Корзина/Саундтреки
    profile/               — профиль, карточка «Синхронизация»
    settings/              — настройки; глубоко — админка под PIN
    player/                — мини-плеер + полноэкранный + audio_service (фон)
```
Пакеты: `just_audio` + `audio_service` (фон/локскрин), `sqflite`, `dio`, `riverpod`,
`path_provider`, `connectivity_plus`, `background_downloader` (докачка при закрытом приложении),
`palette_generator`, `wakelock_plus`, `crypto` (uuid событий).

- **Поток:** играет только скачанное (~24ч запаса); реакции Лайк/Дизлайк/Больше-Меньше/Плохая
  версия; в Потоке удаления нет; статус «Офлайн-запас: 23 часа/полный/мало» (<6ч — предупреждение);
  причина «похоже на лайкнутые/из чарта/новое»; кончился → «Поток закончился» + «Играть скачанное».
- **Мини-плеер** поверх вкладок → тап в полноэкранный. Фон/наушники — `audio_service`.
  Гэплесс/кроссфейд/нормализация −14 LUFS — позже (через ReplayGain/AndroidLoudnessEnhancer).
- **Офлайн-показ:** Поток/Чарты/Библиотека/Профиль живут из SQLite. Онлайн только: докачка,
  обновление чартов, выгрузка событий, бэкфилл обложек.

```
  sync/         — приём батча событий (дедуп по uuid), пересчёт вкуса/статистики
  library/      — лайки/дизлайки/корзина/альбомы на сервере

  storage/      — 500ГБ, приоритеты чистки, восстановление
  admin/        — статус/очередь/устройства/отчёты/ручной синк (под PIN)
  vibe/         — скоринг (перенос scoring.ts/config.ts), центроид, cosine (SQL к pgvector)
  provider/     — оркестрация источников: вызовы Python-сайдкара по HTTP (Яндекс, торренты)
  sidecar/      — HTTP-клиент к Python-сайдкару (те же ручки: /find-audio, /analyze-features…)
```

Кандидаты: роутер `chi`, БД `pgx`+`sqlc`, pgvector (тот же SQL), крон `robfig/cron`, JWT

### 6.1. Развилка Python-специфики (РЕКОМЕНДАЦИЯ)
На Go нет дешёвых эквивалентов ключевого: **yt-dlp** (Яндекс/скачивание), **PANNs**-эмбеддинги
(PyTorch+librosa), **librosa** (настроение), **curl_cffi** (обход Cloudflare для musify/торрентов).
- **Вариант A (рекомендуется):** Go переписывает `apps/api` целиком (оркестрация, БД, бизнес-логика,
  скоринг, контракты). **Python-сайдкар остаётся тонким** — только «руки» (скачать, разобрать) по
  HTTP-JSON. Контракт API↔сайдкар уже HTTP (`SIDECAR_URL`) — Go дергает те же ручки без изменений.
  Часть внешних демонов (slskd, qBittorrent, ffmpeg) при желании Go зовёт напрямую, сокращая сайдкар.
- **Вариант B:** полный отказ от Python — yt-dlp как внешний процесс, торренты anacrolix/torrent,
  эмбеддинги через ONNX-экспорт + Go-runtime, curl_cffi → utls/cycletls. Дольше, рискованнее.
- Рекомендация: этапы 1-6 — вариант A; полный отказ от Python отложить. → **ВОПРОС К ALEX.**

## 7. Схема хранения данных

**Сервер (PostgreSQL) — источник правды** (переносится почти целиком из текущей схемы):
- `tracks` (каталог + `feature_vector` halfvec 2048 + `energy`/`valence` + флаги готовности/версии),
  `track_files` (файлы/качество/громкость/источник, `normalized_key`), `albums`/`album_tracks`,
  `chart_entries`, `curated_artists`, `vibe_decisions`, `rejected_track_files`,
  `prefetch_failed_attempts`, `artist_prefetch_cooldown`, `user` (Alex), `user_liked_tracks`.
- **Упростить:** provider-зоопарк (только Яндекс+торренты), онбординг-сиды (один Alex),
  мультиюзер-денормализация, temporary-quick-skip, legacy-поля `album_tracks`.
- **Новое (в текущей схеме отсутствует):**
  - `sync_events` — идемпотентная очередь событий с телефона (event_uuid unique, kind, payload,
    device_id, applied_at); виды: прослушивание/%дослушивания/лайк/дизлайк/удаление/пропуск/источник.
  - `devices` — реестр телефонов (имя, последний синк, размер музыки, офлайн-запас, версия приложения).
  - `stream_reserve` / `prefetch_plan` — модель запаса Потока на 24ч (горизонт, статус полный/23ч/мало).
  - `trash` — soft-delete с TTL 7 дней (`reason`: вручную/автоочистка/плохое качество/заменено;
    `deleted_at`, `purge_after`; запрет авто-докачки вручную удалённого).
  - `sync_reports` — отчёты синка (добавлено/удалено/не найдено[90дн]/заменено/нет обложки/место).
  - Поля версии релиза на `tracks`/`track_files` (album/single/remaster/remix/live/explicit-E) — сейчас
    только `is_remix`.
  - Флаг/категория «Саундтреки» на `tracks`.

**Телефон (SQLite) — подмножество под 50ГБ** (основа — существующая `db.ts`):
- `downloaded_tracks` (+`pinned` защита), `track_meta`/`features` (энергия/валентность/версия/E),
  `events_queue` (pending события до синка), `charts_cache` (топ-100), `stream_buffer` (очередь
  Потока + причина), `likes`, `trash` (Корзина 7дн + причина), `device_albums`, `vibe_state` (вкус).
- Правила 50ГБ (приоритет вытеснения): Поток → Чарты → Любимое (защита) → Альбомы (целиком).

## 8. API телефон ↔ сервер (черновик контракта, REST)

- `POST /v1/auth/login` {login,password} → {token} (телефон хранит token, дальше без входа; офлайн-старт).
- `GET  /v1/stream/pack?have=<ids>` → треки для пополнения Потока до 24ч (+ причина).
- `GET  /v1/music/{trackId}/file` → аудио (Range) — прямой стрим с auth-заголовком (без прокси-костыля).
- `GET  /v1/music/{trackId}/cover` → обложка ≥600.
- `GET  /v1/charts?since=<date>` → топ-100 по чартам (только проигрываемые, с нормальной обложкой).
- `POST /v1/sync/events` {events:[{uuid,type,trackId,ts,payload}]} → {accepted:[uuid]} (дедуп по uuid).
- `GET  /v1/sync/manifest` → что должно быть на телефоне (сверка/докачка/чистка).
- `GET  /v1/sync/report` → последний отчёт синка (для карточки «Синхронизация» и настроек).
- `POST /v1/track/{id}/bad-version` → сервер ищет замену.
- Админ (под PIN): `GET /v1/admin/status|queue|devices|reports`, `POST /v1/admin/sync`.
- Инвариант: события идемпотентны по uuid; действия пользователя > авто-решений сервера.

## 9. Этапы разработки (1-10)

1. **Скелет Flutter + Go.** Пустое приложение (5 вкладок-заглушек, тема Афиша) + Go (health,
   `/auth/login` Alex, токен). Postgres+SQLite поднимаются, тестовая папка музыки. Проверка:
   телефон логинится, видит сервер, открывается офлайн после первого входа.
2. **Локальный плеер и скачанная музыка.** Go отдаёт файл, Flutter качает в кэш и играет офлайн;
   мини-плеер; `downloaded_tracks`. Проверка: трек скачался и играет без сети.
3. **Синхронизация телефон↔сервер.** `events_queue` → батч на сервер по Wi-Fi, дедуп по uuid;
   карточка «Синхронизация». Проверка: события доходят один раз, переживают офлайн.
4. **Поток.** Сервер готовит пакет 24ч (подбор+чарты), телефон держит запас, статус запаса,
   реакции. Проверка: Поток играет офлайн, дома пополняется до 24ч.
5. **Чарты.** Сервер обновляет топ-100 (крон+ручная кнопка), телефон кэширует офлайн. Проверка: видны без сети.
6. **Библиотека.** Скачано/Любимое/Альбомы/История/Корзина/Саундтреки; удаление через Корзину 7 дней;
   правила 50ГБ. Проверка: удаление и автоочистка по приоритетам.
7. **Качество треков и версии.** Правила готовности (обложка ≥600, не live/karaoke, длительность),
   album version основная, remaster-замена, метка E, «плохая версия»→замена. Проверка: мусор не доходит.
8. **Админка.** Внутри приложения под PIN: статус/очередь/место/устройства/отчёты/ручной синк.
9. **Полировка под «Афишу»** (near-black + лайм + Bahnschrift, обложки, анимации, отклик).
10. **Аудиокниги — позже** (после стабильной музыки; подкасты не делаем).

## 10. Риски

- **Python-специфика** (yt-dlp, PANNs/librosa, curl_cffi, торренты) — нет дешёвого Go-эквивалента
  (см. развилку A/B). Основной риск полного отказа от Python.
- **Перенос каталога** (~3230 треков, ~55ГБ файлов + БД со старой схемой, миграции вручную с 0011) —
  это миграция данных, не старт с нуля; нужна аккуратная выгрузка/сверка.
- **Аудио на Flutter** — фон/локскрин/гэплесс/нормализация громкости требуют настройки `audio_service`
  (в вебе это был ручной Web Audio граф — не переносится, реализуется иначе).
- **Офлайн-конфликты синка** — порядок событий, «последнее действие пользователя главнее»; нужна
  чёткая политика применения на сервере.
- **Стиль «Афиша»** — перенос дизайн-языка из веба (Pixi/GSAP) во Flutter (другой рендер, только референс).
- **Контракт tRPC → REST/Connect** — переопределение API-контракта; формы ответов сохраняемы.
- **iOS** — позже; часть аудио/фона отличается.
