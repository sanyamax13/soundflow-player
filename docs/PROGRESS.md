### Новый Go-сервер РАЗВЁРНУТ на fg (04.09.2026, этап 8 часть 2)

- Бинарь `D:\soundflow2\srv.exe` (кросс-компиляция с brain:
  `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build`).
- `D:\soundflow2\run.cmd` — переменные окружения + запуск, пишет
  `D:\soundflow2\srv.log`. В файле пароль базы — **в git не кладём** (как
  `.env` сайдкара).
- База: контейнер `soundflow2-postgres` (образ `pgvector/pgvector:pg17`,
  тот же, что у старой), `127.0.0.1:5434`, том `soundflow2_pgdata`,
  `--restart unless-stopped`. Отдельная от старой. Миграции 0001–0003
  накатились.
- Слушает `0.0.0.0:8090` (tcp4). Правило файрвола `SoundFlow2-8090` (inbound TCP).
- Автозапуск: задача планировщика `SoundFlow2` (`schtasks /sc onstart
  /delay 0002:00 /ru SYSTEM /rl highest`, запускает `run.cmd`).
- **Деплой нового `srv.exe` (порядок, проверено 06.09.2026):** собрать
  (`GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build`), `scp` на fg под
  временным именем, затем на fg: `Stop-Process -Name srv -Force` →
  **подождать ~8 сек** (Windows не сразу отпускает файл убитого процесса —
  иначе первый `schtasks /run /tn SoundFlow2` даёт `LastTaskResult 1` и
  сервер не поднимается) → `move /Y srv.exe srv.old.exe` → `move /Y
  srv.new.exe srv.exe` → `schtasks /run /tn SoundFlow2`. Проверка:
  `/v1/admin/status` отдаёт `uptime_sec` близкий к 0.
- **fg — слабая машина: Intel N150, 4 ядра.** `/v1/admin/reanalyze`
  (звуковой отпечаток) на ней — дольше **6 минут на трек** (не ~9 с, как
  считалось на этапе 15), сайдкар отдаёт `context deadline exceeded`. 6700
  треков без отпечатка = месяцы при 100% загрузке CPU. **Массовый догон на
  fg не гонять** — считать на brain (RTX 4080), процедура в
  `docs/FINGERPRINT_BACKFILL.md`. Разовый догон уже сделан 06.09.2026
  (этап 33): 8719 из 8781 с отпечатком. Осталось ~62 (`.m4a` + пара битых) —
  не критично.
- Перевод путей сайдкара (из его `.env`):
  `E:\soundflow-data\cache` ↔ `D:\SoundFlow\cache`,
  `E:\soundflow-data\music` ↔ `D:\SoundFlow\music` (env `SIDECAR_*_DIR`).
- **Сквозной прогон на эмуляторе против fg** (`--dart-define=
  SOUNDFLOW_API=http://192.168.1.73:8090`, без adb reverse — реальный IP
  в локалке): «Найти музыку» → заказал Кино — Пачка сигарет → сайдкар на fg
  скачал 320 с Яндекса → строка в каталоге → «скачать на телефон» отдал
  настоящий файл 10.6 МБ (fg-сервер перевёл канонический путь в реальный) →
  в «Моей музыке» 10.1 МБ → играет, позиция тикает 0:24 / 4:26. На телефоне
  не проверялось.
- Хрупкое место: задача `onstart` + задержка 2 мин; если docker не поднялся
  за 2 мин после ребута fg — сервер стартует с базой down и накат миграций
  не повторяет. fg перезагружают редко; укрепить позже (ждать порт 5434 в
  `run.cmd` либо ретрай в сервере).
- На fg два процесса `python -m src.main` (PID .venv и системный Python на
  :8001) — возможно дубль, не наше, сайдкар отвечает.

- Осталось из плана деплоя: сделать `srv.exe` устойчивым к ребуту; когда
  надо — служба вместо задачи планировщика.

## Поиск и скачивание музыки (этап 8, часть 1 — сделано)

Откуда качает старый код (`audio_chain.py`): Яндекс.Музыка 320 → musify →
торренты (nnmclub, rutor, tapochek, rutracker). **YouTube и Soulseek — убрать**
(Alex, TG 17999): из сайдкара не вырезаем, просто гасим в `skip_providers`.
Куда: на fg (там живёт сайдкар и туда физически падают файлы). Телефон сам
ничего не ищет — просит сервер и забирает готовый файл по Wi-Fi.

Готово (не закоммичено на момент записи — коммит следом):
- Go `internal/sidecar/` — HTTP-клиент к старому сайдкару `:8001`
  (`/find-audio`, `/id3-info`, `/yandex/*`). Таймаут 10 мин на скачивание.
- Go `internal/pathmap/` — перевод «канонический путь ↔ реальный путь на fg»
  (перенос `swap_root` из сайдкара). Настройка через env `SIDECAR_*_DIR`.
- Go `internal/acquire/` — оркестровка: фильтр качества (`quality.Screen`) →
  дедуп по `normalized_key` → `/find-audio` → **сверка тегов** (торрент-альбомы
  иногда отдают чужой файл — ловим по ID3) → tier по кодеку/битрейту →
  длительность → обложка из Яндекса → строки `tracks` + `track_files`.
  Отклонённые источники пишем в `rejected_track_files`, чтобы не возвращаться.
- Go `internal/db/catalog.go` — каталог: `TrackByKey`, `InsertTrackWithFile`,
  `CatalogList`, `CatalogSearch`, `TrackFilePath`, `RecordRejected`.
- Ручки: `GET /v1/search?q=` (поиск по каталогу), `POST /v1/tracks/acquire`
  (`{artist,title,duration_sec}` → найти и скачать на fg). `/v1/tracks` теперь
  отдаёт каталог, если он не пуст (иначе тестовые тоны). `/v1/music/{id}/file`
  берёт путь из `track_files` и переводит канонический → реальный.
- Миграция `0003_cover_url.sql` — `tracks.cover_url`.
- Телефон: экран **«Найти музыку»** (`features/search/`) — блок «Заказать
  новое» (исполнитель + название + «Найти и скачать» со спиннером и понятным
  итогом) и блок «Уже на сервере» (поиск по каталогу, тап — скачать на телефон).
  «＋» в «Моей музыке» открывает этот экран вместо тестового списка.
- `api.dart`: `searchCatalog`, `acquireTrack` (10-мин таймаут, человеческие
  тексты ошибок 404/422/503).

**Сквозной прогон на эмуляторе (Go-сервер на brain → живой сайдкар на fg):**
экран рисуется, каталог из настоящих строк; ввёл Coldplay / Yellow →

## Решения (04.09.2026, TG)

- Дизайн «Афиша» один-в-один. Сервер на Go сразу вместо старого, веб-фронт не нужен.
- Только Android. Умный подбор по звуку — не в первой версии, следующим шагом.
- **Входа НЕТ вообще** (не «пароль один раз», а совсем ничего) — плеер личный,
  сервер в домашней сети. Понадобится доступ снаружи — вернём токен.
- **Чарты и альбомы убраны целиком** (и вкладки, и на сервере).
- **Три вкладки: Поток · Моя музыка · Профиль.** Настройки — внутри Профиля.
- «Моя музыка» = весь список скачанного на телефон: размер каждой, общий объём,
  играть / ♥ / удалить, переключатель Все/Избранное. Это и инструмент «что на
  телефоне» + ручная чистка. Отдельной вкладки «Избранное» нет — это фильтр.
- Фильтры по жанрам — потом.
- Личную разметку со старого сохраняем (избранное + удалённые), каталог —
  с нуля. Файлы (~50 ГБ) со старого телефона не переносим; старое приложение
  Alex удалит сам, но **после** финальной синхронизации дома (см. ниже).
- **Источники музыки: Яндекс.Музыка + торренты. От YouTube отказались**
  (Alex, TG 17986). Когда сервер будет искать/качать — это Яндекс и торренты
  через тонкий Python-сайдкар (как в старом `audio_chain.py`), не YouTube.
