# SoundFlow — прогресс

Живой статус нового проекта (Flutter + Go). Читать первым.
План этапов — `SOUNDFLOW_FLUTTER_GO_MIGRATION_PLAN.md` §9. Продуктовые правила —
`SOUNDFLOW_OFFLINE_FIRST_PLAN.md`. Ревизия, с которой всё началось —
`soundflow-migration-review-2026-09-04.md`.

## Где что

- `E:\soundflow` — этот репозиторий (создан 04.09.2026).
- `apps/mobile` — Flutter, только Android. Разработка и сборка APK на brain.
- `apps/server` — Go. Разработка на brain, деплой на fg (заменит старый Bun).
- `docker-compose.yml` — PostgreSQL 17 + pgvector, порт 5433.
- `migration/` — выгруженные со старого сервера списки (избранное, удалённое).
- Старый проект `e:\music-player` — только справочник, не трогаем.

## Решения (04.09.2026, TG)

- Дизайн «Афиша» один-в-один. Сервер на Go сразу вместо старого, веб-фронт не нужен.
- Только Android. Умный подбор по звуку — не в первой версии, следующим шагом.
- **Входа НЕТ вообще** (не «пароль один раз», а совсем ничего) — плеер личный,
  сервер в домашней сети. Понадобится доступ снаружи — вернём токен.
- **Чарты и альбомы убраны целиком** (и вкладки, и на сервере).
- **Три вкладки: Поток · Моя музыка · Профиль.** Настройки — внутри Профиля.
- «Моя музыка» = весь список скачанного на телефон: размер каждой, общий объём,
  играть / ♥ / удалить, переключатель Все/Избранное. Это и инструмент «что на
  телефоне» + ручная чистка. Отдельной вкладки «Избранное» нет — это фильтр.
- Фильтры по жанрам — потом.
- Личную разметку со старого сохраняем (избранное + удалённые), каталог —
  с нуля. Файлы (~50 ГБ) со старого телефона не переносим; старое приложение
  Alex удалит сам, но **после** финальной синхронизации дома (см. ниже).
- **Источники музыки: Яндекс.Музыка + торренты. От YouTube отказались**
  (Alex, TG 17986). Когда сервер будет искать/качать — это Яндекс и торренты
  через тонкий Python-сайдкар (как в старом `audio_chain.py`), не YouTube.

## Этапы

- [x] **Этап 1 — каркас.** (коммиты `55ebdfe`, `8c49004`, `a50e2b1`, `a53eb0c`)
  Flutter 5 заглушек + тема; Go health/login/tracks/music; вход по пропуску;
  Postgres поднимается. Прогон на эмуляторе пройден.
- [x] **Этап 2 — простой плеер + «Моя музыка».** (коммиты `3d51ddd`, `19f49f1`)
  - Вход выпилен целиком (сервер и приложение).
  - Вкладки сведены к трём. Чарты/альбомы удалены.
  - `just_audio` — проигрывание локального файла; мини-плеер снизу.
  - SQLite `downloaded_tracks` (+favorite); `DownloadsRepo`: скачать / удалить /
    в избранное / список / сводка.
  - Экран «Моя музыка»: счётчик песен и объём, Все/Избранное, играть/♥/удалить,
    «＋» — добавить с сервера (пока тестовый список).
  - Сервер: `POST /v1/auth/*` и JWT убраны, ручки открыты.
  - **Сквозной прогон на эмуляторе:** без входа → 3 вкладки → скачать трек →
    играет (ExoPlayer, мини-плеер) → ♥ (сохраняется при переустановке) +
    фильтр Избранное → удалить с подтверждением → 0 песен → убил сервер,
    приложение открывается офлайн, список из локальной базы. На телефоне не
    проверялось.
- [x] **Этап 3 — синхронизация телефон → сервер.** (коммит `efb31d6`)
  - Сервер: миграции (`internal/db/migrations/`, накат на старте), таблицы
    `devices` + `sync_events` (дедуп по `event_uuid`), ручки
    `POST /v1/sync/events` и `GET /v1/sync/report`. Без базы — 503, сервер жив.
  - Телефон: SQLite v2 — таблицы `events_queue` + `kv`. `SyncRepo`: события
    (`like`/`unlike`/`delete`/`download`/`play`) копятся офлайн, уходят батчем
    по кнопке. Действия в «Моей музыке» и старт трека сами кладут событие.
  - Профиль → **Синхронизация**: сколько ждут отправки, когда синхронились,
    кнопка «Синхронизировать сейчас».
  - **Сквозной прогон на эмуляторе:** офлайн лайк/анлайк/играть → «Ждут
    отправки: 3»; синк без сети → «Сервер не ответил», очередь цела; сервер
    поднят → синк → в Postgres ровно 3 события + устройство с размером музыки;
    повторный синк → «Новых событий не было», в базе без изменений; перезапуск
    приложения → очередь и дата последнего синка на месте, новый офлайн-лайк →
    «Ждут отправки: 1» → синк → в базе 4. На телефоне не проверялось.
  - Подключение старых списков из `migration/` — НЕ здесь: ждём, когда Alex
    дома синхронит старое приложение и я перевыгружу полный список (этап 3 плана
    это тоже включал, но без полных данных смысла нет).
- [x] **Этап 4 — Поток (простое радио).** (коммит `747b52a`)
  - Вкладка «Поток»: кнопка «Слушать» (вперемешку / по порядку), переключатель
    перемешивания, список скачанного, активный трек подсвечен.
  - Полноэкранный плеер (`now_playing_screen.dart`): обложка-заглушка, перемотка
    (позиция/длительность), назад/вперёд, пауза, перемешать, сердечко.
    Открывается тапом по нижней плашке и из «Потока».
  - `PlayerController` держит очередь (`ConcatenatingAudioSource`), авто-переход
    к следующему, зацикливание для радио; тап «играть» в «Моей музыке» —
    одиночный трек без цикла.
  - Пропуск трека → событие `skip` в синхронизацию; старт трека → `play`
    (только на смену трека, не на каждый повтор по кругу).
  - Сервер: 3 встроенных тестовых тона (440/554/659 Гц) вместо одного — чтобы
    очередь было чем наполнить до каталога.
  - **Сквозной прогон на эмуляторе:** скачал 3 тона → «Поток» показал список →
    «Слушать вперемешку» → полноэкранный плеер играет, авто-переход между
    тонами, перемотка тикает, ⏭/⏮ переключают, сердечко подхватывает избранное
    текущего трека; тап по плашке открывает тот же экран; события play/skip/
    download дошли на сервер. На телефоне не проверялось.
  - Умного подбора по звуку, серверного пакета Потока на 24ч, статуса запаса,
    «Поток закончился» — здесь НЕТ (следующие шаги). На коротких 3-сек тонах
    события `play` копятся быстро — на реальных треках 3+ мин такого нет; порог
    «дослушал» приедет с переносом `offlineVibe`.
- [x] **Этап 5 — правила качества и версий (перенос из старого).** (коммит `a0bec2b`)
  Только серверная логика, на телефоне ничего не поменялось — так и договаривались
  (Alex, TG 17986: «другим вариантом», без качалки).
  - `internal/quality/` — чистые функции, перенос `apps/api/src/quality/*`:
    - `Screen(artist,title,url)` — acquisition-фильтр: режет live/концерт и
      откровенный мусор (караоке, nightcore, slowed, минусовка…), каверы и
      ремиксы пропускает. Bare «live» в имени («Live Is Life») не трогает.
    - `ReleaseKind` (studio/remaster/remix/acoustic/live/…), `IsExplicit`,
      `IsAltVersion`, `DurationMatch` (с расширенным допуском для ремастера).
    - `ClassifyAudio` — codec-aware tier (mp3 320 ≠ AAC 128 ≠ Opus 128),
      `CompareAudio` / `ShouldReplace` — выбор лучшей версии (lossless > сжатое,
      дальше tier, дальше битрейт).
    - `NormalizeKeyPart` / `NormalizedKey` — ключ дедупа «артист__название»
      (NFKD, убирает диакритику: Beyoncé = Beyonce).
    - Тесты: `screen_test.go`, `audio_test.go`, `key_test.go` — таблицы реальных
      названий.
  - Миграция `0002_catalog.sql` — схема каталога наготове (пустая): `tracks`
    (+`release_kind`/`explicit`/`cover_ok`/`feature_vector vector(2048)`),
    `track_files` (+`quality_tier`/`rejected`), `rejected_track_files`.
    Расширение `vector` включается миграцией.
  - Подключится, когда сервер научится искать/качать музыку (Яндекс + торренты).
    Тогда же — ручка `POST /v1/track/{id}/bad-version` и телефонная кнопка.

- Синглтоны сервисов во Flutter (`AppScope`) → заменить на Riverpod (§5 плана).
- Bahnschrift есть только на Windows — на Android вшить настоящий шрифт «Афиши».
- Деплой Go-сервера на fg (Docker/служба) — когда будет что деплоить.
- Авто-синхронизация по сети (`connectivity_plus`, дома по Wi-Fi) — пока только
  руками кнопкой. Батч ограничен 500 событиями за раз.
- Серверная БД: есть `devices` + `sync_events`. Осталось из §7 плана:
  `trash`, `stream_reserve`, `sync_reports`, поля версий релиза, «Саундтреки».
- На этой машине эмулятор достаёт сервер через `adb reverse tcp:8090`,
  не через 10.0.2.2 (см. README).
