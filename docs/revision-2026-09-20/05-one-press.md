## 3. «ВИДНО ГЛАЗАМИ» — единое место «Активность»

### 3.1 Как синхронизация устроена на самом деле (по коду)

Главное, что надо понимать: **телефон спрашивает, компьютер только отвечает.** Сервер сам телефону
ничего не отправляет и разбудить его не может.

Телефон заходит на компьютер (`apps/mobile/lib/data/auto_sync.dart:25-41`): через 4 секунды после
запуска приложения · когда приложение вернули на экран из фона · раз в 3 минуты, пока приложение
открыто · через 5 секунд после нового события (лайк, удаление).

За один заход (`auto_sync.dart:61-95`) он делает подряд:

1. `POST /v1/sync/events` — отдаёт накопленное (лайки, пропуски, удаления, что дослушал) и
   заодно «я такой-то телефон, связь Wi-Fi, у меня 62,7 ГБ». **Это и есть тот момент, который окно
   потом показывает как «последняя связь».** Сервер на каждое новое `delete` ставит «больше не
   качать» и кладёт песню в очередь на подтверждение (`internal/api/api.go:227-280`).
2. `POST /v1/phone/favorites` — список залайканного.
3. `GET /v1/device/plan` — «есть ли задание с компьютера?». Нет задания — пустой ответ
   (`internal/api/plan.go:37-40`).
4. Есть задание — качает песни по одной, **перед каждой** шлёт `POST /v1/sync/progress` («качаю
   N из M, сейчас такая-то»), в конце `POST /v1/device/plan/ack` — «выполнил», сервер стирает план.
5. Забирает слепок вкуса, если он поменялся.

Окно на ПК опрашивает само себя раз в 2 секунды (`frontend/index.html:2236-2249`): `/api/info`,
`/api/removals`, `/api/jobs` и, только если открыта вкладка «Устройства», `/api/devices`. Отдельно
раз в 60 секунд — плашка «телефон: …».

**Вывод для «видно глазами»:** всё, что происходит на компьютере (скан, пересчёт, скачивание),
показать в реальном времени можно уже сегодня — задержка 2 секунды. Про телефон компьютер узнаёт
только пока телефон сам шлёт `sync/progress`, то есть ровно в секунды закачки; в остальное время
известно лишь «когда был последний раз».

**Что значит «6 ч назад».** Это «когда телефон последний раз поздоровался», а не «6 часов музыка
не обновлялась». Закрыл приложение на телефоне — цифра растёт, хотя всё в порядке. Слово «назад»
читается как упрёк. Предлагаю: «телефон: Wi-Fi, заходил сегодня в 18:46» и зелёная точка, пока
меньше суток.

**Нужен ли «живой канал» (push, постоянное соединение)?** Нет. Опрос раз в 1–2 секунды выглядит как
реальное время, а постоянное соединение — отдельная механика и отдельные поломки. Единственное, что
стоит ускорить, — опрашивать `/api/devices` раз в секунду, пока идёт закачка.

### 3.3 Чего не хватает на сервере

- **С1. Нет «что сейчас в плане» по-человечески.** `/api/phone/state` отдаёт id. Нужна
  `GET /api/phone/plan`: названия, исполнители, байты, сумма. Без неё нельзя написать «+12 песен,
  −3, 0,8 ГБ» ни до нажатия, ни во время. **S · риск низкий · P1.**
- **С2. План нельзя отменить с компьютера.** `ClearDevicePlan` зовётся только телефоном через
  `/v1/device/plan/ack` (`internal/api/plan.go:72`). Значит кнопки «Вернуть» после «Отправить на
  телефон» сегодня физически нет — нужен `DELETE /api/phone/plan`. **S · низкий · P1** (главный
  блокер для «Вернуть»).
- **С3. Нет короткой ленты «что произошло».** `server_log` пишется фразами вроде «план
  синхронизации сохранён: +12 −3» (`sync.go:92`). Нужен второй, человеческий вид тех же записей.
  **M · низкий · P2.**
- **С4. Не видно, чем кончилась задача.** Скачивание исчезает из списка через 8 секунд
  (`jobs.go:96-103`), окно рисует только те, у которых `running` (`index.html:1639-1649`). Итога
  «добавлено 34, пропущено 12» нигде не остаётся. **S · низкий · P1.**
- **С5. Нет «телефон на связи прямо сейчас»** — только «когда был последний раз». Сервер знает,
  когда пришёл последний запрос; достаточно отдать это в `/api/info`. **S · низкий · P2.**
- **С6. У скачивания одного трека нет доли прогресса** — честно написано в `jobs.go:73-77`. Для
  «Найти и скачать» хватит показать `note` из `/api/acquire/log` крупно: «смотрю Яндекс → musify».
  **S · низкий · P3.**

### 3.4 Чего не хватает на телефоне

- **Т1. Телефон качает план МОЛЧА — это главная дыра по «видно глазами».** `AutoSync._trySync`
  зовёт `applyPendingPlan()` без `onProgress` (`auto_sync.dart:87`), хотя сама функция прогресс
  отдавать умеет (`downloads_repo.dart:388-392`). Alex на телефоне не видит ничего: ни полоски, ни
  строки. Видит только окно на ПК. **S — прогресс уже посчитан, его надо просто показать · P1.**
- **Т2. Нет единого места «Активность».** Сегодня разбросано: Профиль → «Скачать музыку» (там есть
  хорошая полоска), Профиль → «Сервер» (счётчик + кнопка), Профиль → «Настройки» → «Журнал».
- **Т3. Итог живёт 4 секунды.** `_syncNow` показывает всплывашку «отправлено 5, скачано 12»
  (`admin_screen.dart:89-91`) — отвернулся, не узнал.
- **Т4. Нет предпросмотра.** Жмёшь «Синхронизировать сейчас» — что произойдёт, неизвестно.
- **Т5. Нет «Вернуть».** Удаление на телефоне стирает файл сразу (`downloads_repo.dart:137-146`),
  спрашивается только причина из четырёх.

### 3.5 Как это должно выглядеть — один порядок для всего

Одна форма для синхронизации, скачивания, скана и удаления — чтобы Alex узнавал её везде.

**ДО нажатия — предпросмотр одной строкой и одна кнопка:**

```
Телефону не хватает 12 песен (0,8 ГБ) · 3 лишние уберём
                                       [ Обновить телефон ]
```

Числа считаются **по плану** (нужна С1), а не по полной разнице каталога — иначе там будут тысячи.

**ВО ВРЕМЯ — строка, полоска, название, «Стоп»:**

```
Телефон качает · 7 из 12   ▓▓▓▓▓▓▓░░░░░   Кино — Пачка сигарет   [Стоп]
```

Тем же видом: «Читаю папку G:\Музыка · 1 240 из 8 967», «Разбираю звук · 340 из 7 657»,
«Ищу Ghost — Mary On A Cross · смотрю Яндекс».

**ПОСЛЕ — карточка итога, которая НЕ исчезает сама:**

```
✓ Готово в 18:52 · добавлено 12, убрано 3, 0,8 ГБ
  одна не скачалась — попробую в следующий раз        [Вернуть] [Понятно]
```

«Вернуть» для плана = отменить план (С2); для удаления на ПК = достать из `_deleted`.

**Ошибки без страшных слов.** Словарь уже написан (`ERROR_DICT`, `index.html:520-541`, 15 фраз), но
применяется не везде: часть мест показывает сырой текст (`_ctxToast("Не получилось: " + e.message)`,
`index.html:907`). Правило: три строки — что не вышло, почему по-человечески, что сделать.

- вместо `connection refused` → «Компьютер сейчас не отвечает. Музыка на телефоне играет как
  обычно — попробую сам через пару минут.»
- вместо `no space left on device` → «На телефоне кончилось место. Скачано 7 из 12. Освободи место и
  нажми «Продолжить».»
- вместо `file used by another process` → «Файл занят другой программой. Песня осталась на месте.»
