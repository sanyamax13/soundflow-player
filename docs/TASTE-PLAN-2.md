# Как плееру понимать, что нравится Alex — план 2

27.09.2026. Задание Alex (TG 22516/22517): «разработать систему, по которой будет определяться, какая
музыка мне нравится или нет; поищи в интернете, на GitHub и Reddit, узнай, как это делает Яндекс и
другие сервисы; составь полный план, присылай по пунктам».

План 1 (docs/TASTE-PLAN.md, 08.09) уже воплощён в коде: события вкуса, кластеры, автоподбор, радио,
«сторож по звуку». Этот план — что делать дальше, с учётом того, что узнали на живых данных.

**Что уже работает в коде:** события вкуса с весами (лайк +5, дослушал +1.5, пропуск −0.3/−0.7,
удаление «не нравится» −5), центры вкуса по звуку (k-means), автоподбор с каналами и разнообразием,
радио «Поток» с учётом вкуса, «Волна» Яндекса, «сторож по звуку» (включается только при точности ≥80 %).

**Главная проблема.** «Ухо» программы — модель CNN14 (PANNs). Она училась различать звуки вообще
(собака, сирена, гитара), а не музыкальный вкус. Проверка 21.09.2026 на данных Alex: по её отпечатку
«нравится» от «не нравится» отличается с AUC 0.55–0.66 — почти монетка (0.5 = случайно). Поэтому
сторож выключен, а «похожее по звуку» иногда не похоже по вкусу.

## 1. Как это делают другие

**Яндекс «Моя волна»** (интервью команды, Хабр 2025–2026):
- смесь из многих моделей: коллаборативная (что слушают люди с похожим вкусом) + «аудиослепок»
  (нейросеть по спектрограмме) + CatBoost (градиентный бустинг по признакам) + большие трансформеры;
- подстраивается с каждым действием, а не раз в сутки: «если адаптируемся раз в сутки — это критически
  медленно»; любое действие, даже бездействие, — сигнал; веса разные (поиск артиста < дослушал + лайк);
- полгода экспериментов ушло на то, как добавлять новое, чтобы это нравилось;
- офлайн-волна на телефоне: векторы треков приходят с сервера, на телефоне — только косинусы и
  умножения (< 100 КБ кода); при пропусках заранее собранная очередь выбрасывается и строится по
  свежим сигналам;
- новое 2026: «гиперконтекст» — время суток, день недели, устройство.

**Spotify:** коллаборативная фильтрация (главное) + анализ звука + тексты/описания; сохранение и
добавление в плейлист — самые сильные плюсы, пропуск до 30 с — надёжный минус.

**Открытые проекты для своей библиотеки (GitHub):**
- AudioMuse-AI (для Navidrome/Jellyfin/Plex): «ухо» MusiCNN (200 чисел на песню) + CLAP (512 чисел,
  связывает звук со словами — «спокойный джаз»), индекс похожести, «звуковой отпечаток вкуса» по
  часто слушаемым с затуханием 30 дней, «путь» между двумя песнями, «алхимия» (смешать нравится/не нравится);
- ListenBrainz Troi — открытый движок «Weekly Jams / Weekly Exploration» на коллаборативных данных;
- Curator — оценка исполнителей по пропускам и дослушиваниям, а не по тегам;
- Digarr, Lidify, Explo — берут «похожих исполнителей» из Last.fm/ListenBrainz для поиска нового.

**Исследования 2025–2026:** сравнение «ушей» для рекомендаций (arXiv 2608.06928): лучшая — CLAP-Music
(первая в 13 из 18 проверок, примерно вдвое лучше речевых моделей); «музыкальные и связанные со словами
модели сильнее чисто звуковых». Поведение пользователя (лайки/пропуски) поправляет то, чего модель
звука не понимает.

**Вывод:** у всех, кто делает хорошо, вкус определяется не одним звуком. Главные источники —
(а) поведение похожих слушателей, (б) твои собственные действия, (в) музыкальный звук, (г) метаданные.

## 2. Новое «ухо»: музыкальная модель вместо CNN14

Кандидаты (все работают на компьютере без интернета):
- **CLAP-Music** (LAION) — лучшая в свежих сравнениях, 512 чисел, понимает слова;
- **Discogs-EffNet / MAEST** (Essentia, UPF) — обучены на 2 млн записей Discogs по 400 стилям;
- **MusiCNN** — лёгкая, проверена в AudioMuse-AI.

Шаги: посчитать отпечатки новой моделью для 11 660 песен (фоном на сервере, ночью); прогнать тот же
инструмент tasteeval (он уже есть) — AUC «нравится/не нравится» для каждой модели; взять лучшую.
Это эксперимент: плеер не меняется, пока не видно выигрыша. Порог — AUC заметно выше 0.66.

## 3. Второй источник: вкус похожих людей

- **Яндекс**: похожие треки/исполнители (часть уже используем для «Волны»), лайки из Яндекса как
  отдельный слабый слой;
- **Last.fm**: похожие исполнители и треки, теги (бесплатный ключ);
- **ListenBrainz**: похожие исполнители/записи, открытые данные.

Даёт главное, чего нет в звуке: «кто любит X, обычно любит Y». Для «нравится/нет» это обычно сильнее звука.

## 4. Одна оценка из всех признаков (как CatBoost у Яндекса)

Признаки песни: отпечаток звука (новое «ухо»), исполнитель и его история у Alex, похожесть по Яндексу/
Last.fm, жанр, настроение, язык, год, темп, энергия, громкость, бас — большая часть уже считается.
Модель — градиентный бустинг на событиях Alex (≈1 700 размеченных + библиотека). Каждая оценка
объяснима: «+0.4 любимый исполнитель, +0.2 похоже на дослушанное, −0.3 похоже на удалённое».

## 5. Сигналы с телефона — точнее

- пропуск: учитывать секунду (<30 с — сильный минус, в конце — почти ноль);
- повтор, перемотка назад — плюс; громкость вверх — слабый плюс;
- смахивание «удалить» уже с причиной — отделять «не нравится» от «не та версия»;
- «Разбор коллекции» (уже есть в коде) — спрашивать про песни, где модель сомневается больше всего:
  один ответ там полезнее десяти случайных (активное обучение).

## 6. «Прямо сейчас»: сессия и настроение

Как у Яндекса — после каждого трека: 2–3 пропуска подряд в одном направлении — сдвигать очередь;
учитывать время суток и день недели (утро/вечер, будни/выходные); офлайн на телефоне — готовые оценки
и векторы с компьютера, на телефоне только косинусы.

## 7. Как проверять честно

Проверка по времени: учим на событиях до даты, проверяем на следующей неделе. Метрики: сколько
удалённых попало бы в топ, сколько дослушанных; доля нового, которое понравилось. Включать в плеер
только то, что проверку прошло (как сторож: порог по точности).

## 8. Этапы

1. Новое «ухо» — эксперимент, сравнение моделей (без изменений в плеере).
2. Похожие исполнители/треки Last.fm + ListenBrainz — в автоподбор и «Волну».
3. Единая оценка (бустинг) + объяснение оценки; включение по результатам проверки.
4. Точнее сигналы с телефона (секунды пропуска, повтор) + разбор коллекции по сомнительным.
5. Сессия и контекст в «Потоке».
6. Настройка весов по живой картине; раз в неделю отчёт «что программа поняла про вкус».

**Нужно от Alex:** согласие на внешние источники (Last.fm, ListenBrainz — отправляют им имена
исполнителей, не файлы); брать ли лайки из Яндекса; какие вопросы «разбора» не раздражают (сколько в день).
