# Догон звукового отпечатка на brain

Зачем: радио «Радио по этой песне» (этап 33) подбирает похожее по
`tracks.feature_vector` (PANNs CNN14, 2048-D, pgvector). fg (Intel N150)
считает один отпечаток >6 минут — `/v1/admin/reanalyze` там нежизнеспособен,
поэтому догоняли на brain (RTX 4080).

**Статус на 07.09.2026: догон практически закончен.** Проверено на fg:
`SELECT count(*), count(feature_vector) FROM tracks` = 8781 / 8719 (99.3%).
Цифра «2049», что стояла тут раньше, устарела ещё к этапу 33. Без отпечатка
осталось ~62 хвоста (`.m4a` и битые файлы — сайдкар их всё равно не берёт).
Радио и умный подбор по вкусу можно строить сразу, ночной прогон не нужен.

Решение: считаем на brain (RTX 4080), пишем в ту же базу `soundflow2`.
Вектор с brain совпадает с вектором сайдкара бит-в-бит (проверено:
cos ≈ 1.0000 на паре готовых треков) — смешивать безопасно.

## Что где

- `D:\sf-fp\venv` — отдельный venv (uv, Python 3.12). **Не** трогает
  ComfyUI. Пакеты: `torch==2.11.0+cu128`, `panns-inference`, `librosa`,
  `psycopg[binary]`.
- `D:\sf-fp\fp_batch.py` — сам прогон.
- `D:\sf-fp\audio\{cache,music}` — копия аудио с fg (`D:\SoundFlow\{cache,
  music}`, ~95 ГБ). Канонический путь в базе `E:\soundflow-data\cache\…`
  переводится в эту копию.
- Модель PANNs — `C:\Users\brain\panns_data\Cnn14_mAP=0.431.pth` (~300 МБ,
  качается один раз).

## Как повторить (если снова накопятся треки без отпечатка)

1. Копия аудио с fg (быстро — tar-стрим одним ssh-соединением, ~130 МБ/с;
   `scp -r` по одному файлу даёт ~4 МБ/с, не годится):
   ```
   ssh soundflow-fg 'tar -C D:/SoundFlow -cf - cache music' | tar -C D:/sf-fp/audio -xf -
   ```
2. Туннель к базе нового сервера (`soundflow2-postgres` слушает только
   `127.0.0.1:5434` на fg):
   ```
   ssh -N -L 5434:127.0.0.1:5434 soundflow-fg
   ```
3. Прогон (берёт только строки с `feature_vector IS NULL`, докоммичивает
   по 20, повторный запуск продолжает с места):
   ```
   D:\sf-fp\venv\Scripts\python.exe -u D:\sf-fp\fp_batch.py --device cuda
   ```
   Скорость ~1.3 трек/с, 6700 треков ≈ 1 ч 20 мин.
4. Сервер подхватывает `feature_vector` на лету (каждый запрос
   `OrderBySimilarity` читает заново) — перезапускать `srv.exe` не надо.

## Известные пропуски

- `.m4a` (~34 шт) — `soundfile`/libsndfile не декодирует, ffmpeg ставить
  ради них не стали. Останутся без отпечатка.
- ~16 файлов (скиты/интервью со спецсимволами в пути) не перенеслись
  tar-ом. Мелочь, при желании докопировать точечно.

## Прибраться после

`D:\sf-fp\audio` (~95 ГБ) можно удалить. `venv` (~4 ГБ) — по желанию;
пригодится, если догон понадобится снова.
