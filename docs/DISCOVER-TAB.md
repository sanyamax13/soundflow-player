## Что сделано

**1. Разделы свёрнуты.** Заголовок с стрелкой ▸/▾ (клавиатурой тоже: Enter/Пробел); внутри раскрытого — подсказка, список и кнопки «Обновить» / «Скачать выбранные» (у свёрнутого их не видно). Открытые разделы обновляются при повторном входе на вкладку; состояние «открыт/закрыт» между запусками не хранится — при каждом запуске всё свёрнуто. Дизлайки Яндекса → чёрный список по-прежнему импортируются тихо раз за запуск, теперь при входе на вкладку (а не при раскрытии лайков: волна их учитывает).
   В шапке раздела — число песен (после первой загрузки: «100 песен», «577 песен · докачать 567»).

**2. Слушать.** У каждой песни на обложке значок ▶ (виден всегда), клик по строке играет; тот же плеер внизу, что и для каталога (пауза повторным кликом, ползунок, ◀◀ ▶▶ и конец песни — соседняя песня того же списка). Полная песня, не обрезок. Устройство:
   - окно → `GET /api/yandex/preview?id=<yandex_id>&artist=&title=` (`cmd/soundflow/preview.go`, **только с этого компьютера**, `localOnly`: иначе Яндекс по токену Alex слушала бы вся домашняя сеть);
   - программа спрашивает качалку `GET /yandex/stream-url` → временная прямая ссылка на mp3 (`api.music.yandex.net/get-mp3/...`, 320 kbps, без заголовков авторизации), проксирует поток окну с поддержкой Range (перемотка), ссылку держит в памяти 10 минут; если Яндекс её уже не принимает (4xx) — спрашивает заново один раз;
   - у старых лайков телефона нет `yandex_id` — качалка ищет песню по артисту и названию (`_find_sync`, как при скачивании);
   - если не вышло — вместо тишины сообщение с причиной («Не получилось включить песню: Яндекс не отдал песню: …» / «качалка ещё запускается — попробуй через минуту»).
   - песни, уже лежащие в каталоге (в лайках помечены «✓ есть»), тоже слушаются через Яндекс — так проще и одинаково.

У песен «✓ есть» (уже в каталоге) кнопки «Удалить» нет — им нечего скрывать. Фильтр — на сервере: волна (и кэш дня, и свежая подборка), лайки Яндекса, старые лайки телефона; ручки `POST /api/discover/dismiss` и `/undismiss` (только с этого компьютера).

Поэтому новый эндпоинт добавлен только в живую копию (копии до правки: `fg-sidecar-src\main.py.bak-before-stream-url-20260919`, `yandex.py.bak-before-stream-url-20260919`), а код записан здесь:

```python
# providers/yandex.py (после wave_candidates)
def _stream_url_sync(track_id: str, artist: str, title: str):
    client = _get_client()
    if client is None:
        return None, None, "нет токена Яндекса"
    track = None
    if track_id:
        try:
            got = client.tracks([track_id]); track = got[0] if got else None
        except Exception as e:
            log.warning("yandex stream-url: tracks([%s]) не вышло: %s", track_id, e)
    if track is None and artist and title:
        found = _find_sync(artist, title, None)
        if found is not None: track = found[0]
    if track is None:
        return None, None, "не нашла песню в Яндексе"
    try:
        infos = track.get_download_info()
    except Exception as e:
        return None, None, "Яндекс не отдал список файлов песни"
    mp3s = sorted((i for i in infos if i.codec == "mp3"), key=lambda i: i.bitrate_in_kbps or 0, reverse=True)
    for info in mp3s:
        try: return info.get_direct_link(), info.bitrate_in_kbps, None
        except Exception as e: log.warning("yandex stream-url: get_direct_link не вышло: %s", e)
    return None, None, "у Яндекса нет mp3 для этой песни"

async def stream_url(track_id, artist, title):
    return await asyncio.to_thread(_stream_url_sync, track_id, artist, title)

# main.py (перед class YandexDislikeItem)
class YandexStreamResponse(BaseModel):
    url: str | None = None; bitrate_kbps: int | None = None; error: str | None = None

@app.get("/yandex/stream-url", response_model=YandexStreamResponse)
async def yandex_stream_url(track_id: str = "", artist: str = "", title: str = ""):
    from .providers.yandex import stream_url
    url, bitrate, err = await stream_url(track_id, artist, title)
    return YandexStreamResponse(url=url, bitrate_kbps=bitrate, error=err)
```

## Настоящая причина ошибки «только с самого компьютера» (20.09.2026, TG 20090)

Второе фото Alex: «…(запрос пришёл с 192.0.2.1)». Wails v2.15 (`pkg/assetserver/assetserver_webview.go`, `if req.RemoteAddr == "" { req.RemoteAddr = "192.0.2.1:1234" }`) подписывает каждый запрос НАСТОЯЩЕГО окна заглушкой 192.0.2.1:1234, поэтому защита `localOnly` не пускала окно вообще (меню правой кнопки и «Открытия» за ней). Исправление этапа 125 (свои LAN-адреса ПК) помогало только браузеру по 192.168.x.x. Теперь: `APIRouter()` (путь окна) ставит метку в контекст (`markFromWindow`), `localOnly` пускает по метке или по своему адресу; по сети 192.0.2.1 не пускается. Тест `TestLocalOnlyWindowVersusNetwork`, мутационная проверка. Ветка `window-localonly`, v11.
Урок: допущение про поведение чужой библиотеки (Wails) надо проверять по её коду/в настоящем окне, а не считать очевидным; проверка «в настоящем окне» — через порт отладки WebView2 (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9224` при запуске, `scratchpad/dedupe/wails_cdp_check.mjs`; порт после проверки не оставлять — перезапустить без него).
