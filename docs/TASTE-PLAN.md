## 1. Сигналы (что собираем с телефона)

| Сигнал | Что значит | Вес |
|---|---|---|
| Лайк (сердечко) | явное «нравится» | **+3** |
| Песня доиграла сама (complete) | слушал целиком | **+1** |
| Прослушано ≥ 80% | почти целиком | **+1** |
| Прослушано 30–80% | нейтрально/слабый плюс | 0 |
| Пропуск до 30% / до 20 сек | не зашло | **−1** |
| Снял лайк (unlike) | передумал | −1 (гасит прошлый +3) |
| Дизлайк / удалил, причина «не нравится» | явное «нет» | **−4** |
| Удалил, причина «не та версия» | к версии, не к песне | 0 для вкуса (это сигнал качеству) |
| Повтор трека подряд | очень зашло | **+2** |

**Чего сейчас нет и надо добавить на телефоне** (делать при Alex, нужен тест):
- в событие `skip` класть `{position_ms, duration_ms}` — сейчас пропуск без
  позиции, «сколько прослушано» не посчитать;
- новое событие `complete` — песня закончилась сама (не пропуск);
- (по желанию) `repeat`.

Контекст тоже важен (из статьи Deezer): пропуск в «Потоке»/радио — слабее,
чем пропуск из своего плейлиста. На первом этапе не усложняем, вес один.
Учитываем «уверенность»: один пропуск — шум, три пропуска одной песни —
сигнал. Повторяющиеся сигналы весомее разовых.

## 2. Оценка

Считаем на компе, обновляем после каждой синхронизации.

**По песне** `score_track` = сумма весов её событий, сглаженная по времени
(старые события весят меньше: множитель 0.5 за каждые ~90 дней).

**По исполнителю** `score_artist` = среднее `score_track` его песен в
каталоге, взвешенное по числу прослушиваний (1 песня с +3 — не то же, что
10 песен со средним +2).

**Похожесть по звуку.** У каждого трека есть 2048-мерный вектор
(`feature_vector`). «Профиль вкуса» = центр(ы) масс векторов треков с
`score_track > 0`. Кандидата (новый трек) оцениваем по близости к профилю:
`sim_score` = косинус к ближайшему «любимому кластеру».

**Итог кандидата на скачивание:**
`rank = 0.5·score_artist_norm + 0.3·sim_score + 0.2·новизна_релиза`
(новизна — свежий альбом любимого артиста получает бонус).

## 3. Что программа делает с оценкой

### 3.1 Автоподбор (что качать)
Раз в N дней (или по кнопке в окне):
1. Источники кандидатов:
   - новые релизы исполнителей с `score_artist > порог` (Яндекс: релизы
     артиста);
   - «похожие артисты» от Яндекса для топ-любимых;
   - треки, похожие по звуку на профиль вкуса, которых нет в каталоге
     (искать по названию через цепочку источников).
2. Каждого кандидата — через **правила раздела 2 RULES.md** (качество,
   не обрезок, язык, не в блок-листе, не дизлайкнут).
3. Отранжировать по `rank`, взять top-K по бюджету.
4. **Не качать молча.** Кандидаты идут в окно ручной синхронизации отдельным
   списком «Предлагаю по вкусу» с галочками. Alex решает.

### 3.2 Регулировка «Потока» (радио)
`/v1/stream/order` уже упорядочивает очередь по похожести к seed. Добавить
поправку на вкус:

- опускать/пропускать треки исполнителей с `score_artist < 0`;

## 4. Этапы

1. **Телефон: сигналы.** `skip` с позицией, событие `complete`. Мелкая
   правка Flutter, но нужен тест на устройстве.
2. **Сервер: таблицы и подсчёт.** `taste_track(track_id, score, updated_at)`,
   `taste_artist(artist, score, plays, updated_at)`. Пересчёт после
   `SaveSync`. Ручка `/api/taste` для окна (посмотреть топ/антитоп).
3. **Сервер: профиль по звуку.** Кластеризация `feature_vector` любимых
   (k-means на 3–5 центров), `sim_score` для кандидата.
4. **Автоподбор.** Сбор кандидатов + ранжирование + список в окно
   синхронизации. Переиспользует `acquire` и правила.
5. **Поток.** Поправка на вкус в `OrderBySimilarity`.
6. **Окно.** Вкладка «Вкус»: топ-исполнители, что программа предлагает,
   ползунок «сколько нового качать».

Этапы 1–2 — фундамент, дают уже пользу (видно вкус). 3–5 — само «умное».
Делать после переезда на комп и ручной синхронизации (пункты 1–3 дороги).
