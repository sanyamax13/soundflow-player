## Что тратит впустую

1. **Скан папки читает начало КАЖДОГО файла заново.** `StartScan` (`cmd/soundflow/jobs.go`)
   для каждого из 8967 аудиофайлов делает `cuesplit.FindFor`, `readTags`, разбор имени,
   `quality.Screen`, `NormalizedKey`, и только потом `TrackExistsByKey`. Прикидка (Python, чтение
   первых 64 КБ каждого файла как «чтение тегов»): обход папок 0,15 с, чтение файлов
   7,3 с при холодном кэше диска и 0,64 с при горячем. Запускается при каждом возврате
   фокуса окна (14.09.2026, Alex): журнал 19.09.2026 06:44–06:45 UTC — 4 скана за 45 с,
   каждый «пропущено 8967». Идея: помнить уже виденные файлы (путь + размер + время
   изменения, в том числе отвергнутые) и читать только новые; плюс не запускать скан чаще
   раза в минуту.
2. **Модель отпечатков грузится при каждом запуске.** Рабочий набор программы ~400 МБ
   (`cnn14.onnx.data` 323 МБ), а нужна модель только когда добавляются новые песни.
   Идея: грузить по требованию и выгружать после простоя.
3. **(уже исправлено 19.09.2026, этап 118)** при запуске пересчитывались отпечатки/волны
   для 5833 треков с моргающими окнами ffmpeg.
