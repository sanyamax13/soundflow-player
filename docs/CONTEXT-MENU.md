## Как устроено

**Окно (`cmd/soundflow/frontend/index.html`):** `contextmenu` на `#tree` — по строке песни (`.drow`) и по плитке-папке (`.dtile`). Меню закрывается по клику мимо, Esc, прокрутке, смене окна;
не вылезает за край. Действия с вопросом — своё окно (`_ctxConfirm`), по умолчанию фокус на «Отмена» (случайный Enter ничего не удалит). После действия — сообщение внизу (`_ctxToast`).
Заодно у плеера теперь своя очередь `queue` (раньше очередью был список на экране, и при переходе по папкам она сбрасывалась — «Играть папку» так не работало бы).

**Телефон** — «живой» = устройство с самым свежим заходом (`localdb.LatestDevice`; в базе две записи «Samsung SM-S936B», старая от 08.09 не трогается).
Песня «на телефоне» = по событиям (`DeviceTrackIDs`) минус план remove плюс план add. На песне один пункт: «Убрать с телефона» или «Добавить на телефон». На папке два пункта со счётчиками
(«Добавить всю папку на телефон (N)», «Убрать всю папку с телефона (M)») и окно с числом песен и размером; хватит ли места на телефоне, программа не проверяет.
Выполняется при ближайшем заходе телефона (план `sync_plans`). **Меню ДОПОЛНЯЕТ план (`MergePlan`), а не заменяет** (старый `SavePlan` в окне «Синхронизация» заменяет целиком) — невыполненный план не теряется.

**Убранное с телефона не возвращается «Докачать ещё»:** при ack плана (`ClearPlan`) комп записывает событие `delete` с причиной `pc_removed` (без метки «больше не качать» и без сигнала «вкуса»),
а `NextLibraryBatch` пропускает песни, у которых последнее событие — такое `delete`. Снова добавили на телефон — телефон присылает `download`, песня опять доступна.
(Телефон при выполнении плана событий не шлёт — раньше комп считал, что песни всё ещё там; заодно поправлено.)

**Удалить навсегда** (`hDeleteForever`, `POST /api/tracks/delete-forever {ids}`) — как кнопка «Удалить полностью» в карточке телефона (TG 19160), но для песни и для папки, с переносом дерева:

1. песня уходит с телефона (в план remove живого телефона, дополняем);
2. убирается из каталога;
3. её ключ получает метку `blocked` («больше не качать»);
4. файл **не стирается, а переносится** в `<диск файла>\_deleted\<дата-время>\<путь без буквы диска>` (например `G:\_deleted\20260919-210000\музыка\HitZone\…`): тот же диск — мгновенное переименование,
   вложенные папки сохраняются, вернуть можно перетаскиванием. Опустевшие папки убираются (папка-источник из настроек и папки прямо под корнем диска — нет).

Песня, чей файл не переносится (занят), остаётся нетронутой целиком (файл, каталог, без метки), в ответе считается в `failed`. Файла на диске уже нет — песня всё равно уходит из каталога.
Больше 24 песен: **сервер сам сохраняет копию базы** (`VACUUM INTO <папка_базы>\_backup\soundflow-<время>-before-delete.db`; не получилась — ничего не удаляется), а окно просит напечатать слово «удалить».
Скан папки теперь не заходит в папки `_deleted` (иначе скан корня диска вернул бы перенесённое).
Стереть совсем (без `_deleted`) — только если Alex скажет «стирать совсем» (для «убрано на телефоне» так и сделано, TG 19943); сейчас нет.
**Как вернуть удалённое:** положить файлы из `_deleted` обратно на место, затем снять метку «больше не качать» и пересканировать — пока это делаю я по просьбе Alex (кнопки «Вернуть» нет).

**Показать в проводнике** — `POST /api/reveal {track_id}` (`explorer.exe /select,"путь"`), **Открыть папку** — `POST /api/open-folder {path}` (только папка, лежащая выше файла каталога; корень диска и чужие пути — 403).
Все команды, что меняют файлы, план или запускают проводник (`/api/phone/plan`, `/api/tracks/delete-forever`, `/api/reveal`, `/api/open-folder`), — только с этого компьютера (`localOnly`):
`/api/*` висит и на телефонном сервере 0.0.0.0:8091 (доступно всей домашней сети). Старые ручки (`/api/devices/{id}/track/delete`, `/sync-plan`…) по-прежнему открыты всей сети — вне этой правки.
